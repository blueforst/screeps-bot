# 战争双人组有限回身反击设计

## 背景

W2N58 实战中，战争攻击者在 `(35,3)` 持续攻击 `(34,2)` 的 rampart，配对 healer 位于 `(36,4)`。敌方远程治疗单位停在 `(37,5)`，与攻击者相距 2 格。现有逻辑只会攻击相邻敌人；攻击者继续提交拆墙意图，单次控制台移动也会被角色逻辑覆盖，因此无法利用敌人短暂贴近的机会。

此前已经明确禁止近战小队持续追逐会逃跑的敌方 creep。本次优化必须保留该约束，只增加一次、可自动终止的回身反击机会。

## 目标

- 敌方危险 creep 位于攻击者 2 格内时，允许攻击者尝试一步贴身。
- 不要求目标可被一刀击杀；只要目标具有 `ATTACK`、`RANGED_ATTACK` 或 `HEAL` 有效部件即可。
- 接近预算只有一次移动。目标拉开后立即恢复原有建筑或 breach 目标，不连续追击。
- 若目标在下一 tick 仍相邻，沿用现有相邻攻击逻辑持续攻击，直到目标死亡或离开相邻范围。
- 配对 healer 占据唯一贴身格时，允许同 tick 协同让位，但不能破坏双人组相邻关系。
- 敌方 rampart 保护下的 creep 不参与回身反击。

## 方案选择

### 采用：一 tick 反击状态与一次移动预算

攻击者在目标房执行正常战争目标前，扫描 2 格内未受敌方 rampart 保护的危险 creep。只有存在一步即可进入攻击距离的可走位置时才创建短期反击状态，并提交一次移动。

反击状态保存目标 ID、创建 tick 和原 breach ID。有效期仅覆盖创建 tick 与下一 tick：

- 下一 tick 目标相邻时直接攻击；只要目标保持相邻，现有相邻攻击逻辑可以继续攻击。
- 下一 tick 目标不再相邻时清除反击状态，不再向目标移动。
- 清除后保留并恢复仍存在的 `_warBreachTargetId`，继续原拆墙工作。
- 同一目标仍停留在 2 格内时不再次创建反击状态；只有它先离开 2 格范围后重新靠近，才视为新的反击机会。

若唯一可用贴身格被配对 healer 占据，攻击者记录需要交换的方向。healer 在同 tick 看到攻击者的反击状态后，移动到攻击者原位置，使两者交换位置。交换后两只 creep 仍然相邻，治疗逻辑不变。若无法形成安全交换，则放弃本次反击，不挤开其他友军。

### 未采用：持续追到攻击距离

命中概率较高，但会重新引入被远程单位风筝、长期中断拆墙的问题。

### 未采用：仅维持现有相邻攻击

风险最低，但无法利用敌人停在 2 格外且一步可贴身的明显失误，也无法处理 healer 占据唯一进攻格的常见双人组站位。

## 决策顺序

目标房内每 tick 按以下顺序执行：

1. 攻击未受 rampart 保护的相邻敌方 creep。
2. 处理上一 tick 创建的反击状态：相邻则攻击，否则清除并恢复原目标。
3. 若当前没有反击状态，寻找 2 格内危险敌人并评估一步贴身位置。
4. 可直接走入空闲贴身格时提交一次移动；唯一贴身格由配对 healer 占据时请求交换。
5. 没有可行反击时，继续现有核心设施、路径 breach 和残余屏障逻辑。

反击目标按距离、当前生命值、战斗威胁排序；距离相同时优先生命较低者。该排序只决定一次尝试对象，不增加追击预算。

## 状态与清理

攻击者 memory 增加短期字段：

```ts
interface WarCounterstrikeState {
  targetId: Id<Creep>;
  createdAt: number;
  approachX: number;
  approachY: number;
  healerSwap?: boolean;
}
```

攻击者另保存最近一次已消耗机会的目标 ID。只要该目标仍在 2 格内，候选扫描就排除它；目标消失、进入 rampart 或离开 2 格后清除抑制 ID。

反击状态在以下任一条件成立时删除：目标消失、目标进入敌方 rampart、超过下一 tick、目标不相邻、攻击者离开目标房或战争搭档状态失效。任务停止和 creep 死亡依赖现有 Memory 清理，不需要独立任务级状态。

## 测试策略

- 2 格内危险敌人且存在空闲一步贴身格时，攻击者提交一次接近移动并记录状态。
- 下一 tick 目标仍相邻时攻击目标。
- 下一 tick 目标仍为 2 格时清除状态并恢复 tracked breach，不再次移动向敌人。
- 同一目标持续停在 2 格内时不会反复触发；离开 2 格后重新靠近才获得新的一次机会。
- 目标位于 3 格或更远时不触发反击。
- 目标受敌方 rampart 保护时不触发反击。
- 唯一贴身格由配对 healer 占据时，两者提交交换移动，且仍保持配对。
- 唯一贴身格由其他友军占据时放弃反击并继续拆墙。
- 建筑 breach 仍存活时，一次反击失败后继续攻击同一 breach，不重新选远处目标。

## 验证与部署

- 先运行新增测试并确认它因缺少有限反击行为而失败。
- 实现最小逻辑后运行近战攻击者与 healer 定向测试。
- 运行 `npx tsc --noEmit`、完整 Jest、`npm run build` 和 `git diff --check`。
- 提交到 `main` 并运行 `npm run push`。
- 通过 shard1 实时数据确认新 deploy tag，并观察攻击者最多接近一次；敌人拉开后 rampart hits 继续稳定下降。
