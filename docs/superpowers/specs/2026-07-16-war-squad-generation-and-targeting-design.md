# 战争双人小队代次与目标优先级设计

## 背景

现有战争任务用固定配置名表示一名近战攻击者和一名治疗者，并在每 tick 同时用完整双人组资源库存决定是否保留这些配置。攻击者先完成强化后，实验室库存自然减少，控制器会把“当前一代尚可完成强化”和“下一代完整库存尚未补齐”混为同一个状态，从而删除仍在排队的治疗者。当前的临时修复改用存活 creep 的未强化部位估算需求，虽然解除了这一次阻塞，但需求会随成员死亡、生产、跨房和重复配置而变化，不能作为稳定的代次边界。

实时战斗还暴露了第二个问题：核心设施被摧毁后，攻击者会先追逐无战斗能力且与自己同速的运输 creep，随后又会越过大量无防护建筑，优先拆除百万 hits 的外围 wall/rampart。这会把剩余寿命消耗在无法追上的目标或不必要的障碍物上。

## 目标

- 连续战争任务以显式代次管理双人组，不再从瞬时 creep 快照推断整代生命周期。
- 当前代的强化放行闸门一旦开启，不因实验室库存被本代消费而重新关闭。
- 出发前损失只补当前代缺失槽位；出发后破组时让幸存者继续行动，并创建完整下一代。
- 不因资源暂时不足删除已经排队、生产中或存活的当前代成员。
- 初次放行前同时验证强化矿物和实验室能量，避免 creep 生成后因实验室缺能量永久停留。
- 战争攻击者优先摧毁战略和无防护功能设施，只在通往更高优先目标的路径确实被挡住时拆 wall/rampart。
- 不主动追逐无战斗能力的远处 creep；相邻时仍可顺手击杀。
- 无损接管部署时已经存在的旧格式战争任务和 creep。

## 非目标

- 不改变 T3 双人组的身体部件、单个 creep 生成能量成本或强化种类。
- 不增加第三种战争角色，也不实现多支完整双人组同时集结。
- 不改变普通防御、Power Bank 小队或其他非战争 creep 的目标策略。
- 不为无害 creep 实现速度预测、包抄或多人围堵；远处无害 creep 由自然离开、寿命结束或相邻机会攻击处理。

## 方案选择

### 采用：显式代次和单向强化闸门

每个战争任务只维护一个正在准备或执行的 `activeGeneration`。代次拥有独立配置名和强化任务 ID。初次完整资源准备成功后打开 `boostGateOpenedAt`；该字段只写一次。闸门打开后，后续资源不足只改变物理准备状态和补货任务，不撤销配置、不清队列，也不让代次退回未放行状态。

出发前成员死亡时，连续任务在同一代补回缺失槽位。任一成员离开来源房后，该代进入 `deployed`。此后任一成员死亡都视为破组：幸存者标记为脱离编队并继续执行角色逻辑，控制器立即创建完整下一代。这样不会让新成员跨多个房间追赶老成员，也不会浪费仍有战斗能力的幸存者。

### 未采用：持续按当前存活部位重算整队

改动小，但成员在排队、生产和死亡之间切换时需求不稳定；无法表达“本代已放行”，会继续产生队列被撤销和状态互相矛盾的问题。

### 未采用：任一成员死亡就回收幸存者并重造整队

状态简单，但会主动浪费仍有寿命和完整强化的成员，在长途战争中成本过高。

## 数据模型

在战争任务上新增以下持久状态：

```ts
type WarGenerationPhase = "preparing" | "assembling" | "deployed";

interface WarGenerationState {
  id: number;
  phase: WarGenerationPhase;
  createdAt: number;
  boostTaskId: string;
  boostGateOpenedAt?: number;
  deployedAt?: number;
  configNames: {
    meleeAttacker: string;
    healer: string;
  };
}
```

`WarTask` 增加 `generationCounter` 和 `activeGeneration`。新格式配置名为：

```text
<sourceRoom>:war:<targetRoom>:g<generationId>:<role>:0
```

强化任务 ID 为：

```text
war:<sourceRoom>:<targetRoom>:g<generationId>
```

代次 ID 只增不减。配置名仍保留 `:meleeAttacker:` / `:healer:` 片段，因此现有通过字符串替换寻找搭档的逻辑可以继续使用，并且不同代成员不会被错误配对。

## 代次状态转换

### 1. 创建与准备

连续任务没有活动代次时递增 `generationCounter`，创建 `preparing` 代次。控制器用完整 T3 双人组需求调用强化准备逻辑，但在矿物和实验室能量都未满足前不创建 creep 配置，也不进入 spawn 队列。

准备逻辑返回 ready 时写入 `boostGateOpenedAt`，将代次切换为 `assembling`，创建并排队两个角色配置。闸门打开后永不清除。

### 2. 集结与强化

`assembling` 阶段根据本代两个槽位计算尚未完成的强化需求：

- 存活或生产中的 creep 按仍存活且尚未获得目标强化的部件计数。
- 已排队但尚未生成的槽位按完整身体计数。
- 已完整强化的槽位需求为零。
- 同一矿物被两个角色共同使用时合并数量。

该动态需求只用于补货和判断实验室的物理状态，不再控制配置是否存在。成员即使已经生成，也会在角色 `prepare` 阶段等待实际强化完成，不会无强化出发。

### 3. 出发

本代任一成员首次离开来源房即把代次切换为 `deployed` 并记录 `deployedAt`。形成该转换时释放本代实验室预约和运输任务；已经完整强化的成员不再依赖实验室分配。

### 4. 成员损失

- `preparing` 阶段尚无成员，不存在补员。
- `assembling` 阶段缺少一个槽位时，连续任务仅重建该槽位；闸门保持开启，另一成员及其配置不变。
- `deployed` 阶段缺少任一槽位时，本代破组。仍存活的成员写入 `_warDetached = true`，继续战斗；旧配置保留到该成员死亡后再清理。控制器同 tick 创建新的完整 `preparing` 代次。
- 两名成员同时死亡同样直接创建下一代，不需要幸存者处理。
- `oneShot: true` 仍保持“一次队列”语义：不会创建下一代，也不会重新排队已经生成过的槽位；破组后只让幸存者继续行动。

角色的搭档等待逻辑在 `_warDetached === true` 时关闭。脱离编队的攻击者继续选择战争目标；脱离编队的治疗者继续自疗，并可在同房间协助其他攻击者，但不会阻止新一代集结或与新一代建立固定配对。

## 强化资源与能量

`prepareBoosts` 接收的需求代表当前代实际需要的矿物数量。共享强化接口增加可选的 `requireLabEnergy` 选项，默认值为 false，战争代次调用时显式传 true；这样不会改变既有 Power Bank 流程的状态转换。每个强化实验室同时需要：

```text
实验室能量 = 矿物数量 / LAB_BOOST_MINERAL * LAB_BOOST_ENERGY
```

战争强化准备为矿物和对应能量分别创建实验室补给步骤，能量从来源房 storage/terminal 搬运。`checkBoostReadiness` 在 `requireLabEnergy` 开启时同时检查每个分配实验室的目标矿物和能量；`prepareCombatBoost` 在发出单次 `boostCreep` 意图前至少检查 `LAB_BOOST_MINERAL` 和 `LAB_BOOST_ENERGY`。

初始完整需求不足时任务保持 `preparing` 并继续尝试本地搬运或跨房补货，不创建战争 creep。闸门已经打开后，即使补货暂时失败，也只记录 `boostStatus` / `failReason`，不把战争任务置为失败，不删除配置，不取消队列或正在生产的 creep。

## 战争目标优先级

攻击者在目标房内按以下顺序决策：

1. 相邻且未站在敌方 rampart 上的敌方 creep；沿用现有即时攻击逻辑。
2. 战略设施：spawn、tower、storage、terminal、invader core；保持现有类型顺序。
3. 未受敌方 rampart 保护且具有 ATTACK、RANGED_ATTACK 或 HEAL 有效部件的敌方 creep。
4. 未受敌方 rampart 保护的其他非屏障功能设施：power spawn、nuker、lab、observer、link、extension、extractor，以及未列举的非 wall/rampart 敌方设施。按类型优先级后取距离最近者。
5. 受 rampart 保护的功能设施；仍以设施为目标，由路径规划选择实际需要拆除的首个 rampart/wall。
6. 残余敌方 rampart；只有在不存在更高优先目标时才作为清场目标。

远处、无战斗部件的敌方 creep 不作为移动目标。攻击者不会为了追逐同速运输 creep 放弃建筑清理；此类 creep 若进入相邻格仍会被即时攻击。

选定第 2、3、4 或第 5 类目标后，继续使用现有 `findFirstBreachOnCombatPath`。wall/rampart 只有作为通往该目标的首个实际障碍时才写入 `_warBreachTargetId`。现有规则继续把三格内存在敌方 RANGED_ATTACK creep 的 wall 设为高成本，从而优先寻找不受远程火力覆盖的破口。已经锁定的目标房 breach 在结构被摧毁前保持稳定，避免拆到一半回走。

若只剩无害敌方 creep 而没有敌方结构，攻击者不追击，保持在房间内部；战争任务等待这些 creep 离开或死亡后再进入 clear debounce。

## 旧状态迁移

部署后首次处理没有 `activeGeneration` 的旧任务时执行一次惰性迁移：

- 若存在旧格式存活、生产中或排队成员，创建第 0 代并沿用原配置名与原强化任务 ID；已有队列不取消。任一成员已经离开来源房时标记为 `deployed`，否则标记为 `assembling` 且视为闸门已打开。
- 若不存在旧格式存活、生产中或排队成员，删除空闲旧配置，设置 `generationCounter = 0`，随后正常创建第 1 代。
- 迁移不 suicide creep、不取消正在生产的任务，也不改变战争目标房和路线。

旧代或破组代的配置由前缀扫描清理：有存活或生产中成员时保留；成员消失后删除。当前活动代配置永远不被该清理过程误删。

## 遥测与控制台

战争遥测为每个任务增加：

- `generationId`
- `generationPhase`
- `boostGateOpen`
- `generationAge`
- `deployedAge`

现有 `boostStatus` 表示实验室当前物理准备状态，不再承担“是否允许本代存在”的含义。`warStatus` 同时展示活动代配置、队列和 creep，便于区分“已放行但正在补充单个成员资源”和“初代尚未放行”。

`stopWarRoom`、任务完成和显式清理会释放活动代强化预约，并扫描所有代次配置；存活成员按现有停止参数处理。

## 测试策略

### 代次与强化

- 初代完整矿物或实验室能量不足时不创建配置。
- 初代 ready 后闸门打开，并且实验室库存被攻击者消费后仍保留治疗者队列。
- 闸门打开后资源短缺或补货失败不会删除排队、生产中或存活成员。
- 出发前攻击者死亡时只补攻击者，治疗者不重建。
- 任一成员离开来源房后死亡，幸存者标记 detached，并生成配置名不同的完整下一代。
- 新一代成员不会与旧代幸存者配对。
- `oneShot` 任务破组后不创建下一代。
- 无成员的旧任务迁移为第 1 代；有旧成员时无损迁移为第 0 代。
- 实验室矿物充足但能量不足时 readiness 为 false；补足能量后为 true。

### 攻击目标

- 核心设施存在时保持核心设施优先。
- 无核心设施时，未受 rampart 保护的战斗 creep 优先于普通功能建筑。
- rampart 内的战斗 creep 不会覆盖安全功能建筑目标。
- 无防护 extension/lab 存在时，不选择远处无害 creep 或残余 rampart。
- 通往功能建筑的路径被 wall 挡住时，选择路径上的第一面 wall。
- 已锁定 breach 在结构存活期间不切换。
- 只剩远处无害 creep 时不产生追击移动目标。

### 验证与部署

- 运行战争控制、近战攻击者、治疗者和强化准备的定向测试。
- 运行 `npx tsc --noEmit`、完整 Jest 测试、`npm run build` 和 `git diff --check`。
- 部署后确认 `runtime.lastDeployTag` 对应新提交。
- 通过 `analytics.war` 验证两个任务创建新代、配置进入队列、完成 T3 强化并自行出发。
- 在 E2N54 / W2N58 实时确认攻击者不再追逐无害同速 creep，也不在无防护功能建筑仍存在时锁定残余 wall/rampart。

## 失败处理

- 来源房不可见或实验室不足时，未放行代保持 `preparing` 并写明原因；不创建半成品小队。
- 闸门打开后的补货故障不撤回代次，只让尚未强化完成的成员在来源房等待。
- 代次状态缺失或旧数据不完整时走惰性迁移，不删除无法确认归属的存活 creep。
- 战争任务达到既有 staging 超时前仍未形成可出发代次时沿用现有失败策略，避免永久占用实验室和任务状态。
